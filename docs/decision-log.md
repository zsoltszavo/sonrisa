| D18 | 2026-10-04 | Domain-core details settled while implementing S2: (a) USGS magnitude is **rounded to one decimal before bucketing**, so the Severity agrees with the "M 6.0" USGS shows in its title (5.95/5.96 → 4); (b) **apostrophes are read both ways** when matching Keywords: "Pāpa‘ikou" matches `Papaikou`, "Côte d’Ivoire" matches `Ivoire` (cost: `ikou` also matches); (c) a Notification's recipient is a **(User, Channel Destination)** pair, which refines D6's "(user, event, channel)" so a user's personal and team Slack destinations both receive it; (d) an Escalation goes only to already-notified recipients that **still have a matching rule**, and only when the Severity is **above the highest Severity that recipient was already notified about** (so M5.9→6.0→5.9→6.0 escalates once; Notifications must store the Severity they reported, S3); (e) Severity is a literal `1 \| 2 \| 3 \| 4 \| 5` type; Channel keys are plain strings so a new provider needs no shared-enum edit (D11) | (a) The plan writes edges as "4–4.9", so magnitudes are one-decimal values, and a user reading "M 6.0" expects the M6 rule to fire; (b) the saved USGS sample has ʻokina place names and French elisions are common in GDACS/news text; (c)/(d) respect the user's current rules and destinations | Raw float edges (5.96 → 3 while the title says M 6.0); apostrophes as word breaks only (`Papaikou` fails) or as joins only (`Ivoire` fails); one Notification per Channel type; escalating to everyone ever notified; comparing with the previous version only (review CR14: flip-flopping revisions re-escalate) |
